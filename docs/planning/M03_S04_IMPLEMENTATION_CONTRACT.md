## Scope
Slice 04 introduces a framework-neutral immutable `EvidenceSourceExplanationReadModel` bound to one reviewed `CredentialCardReadModel` and its exact authoritative `EligibilityAssessment`.

The view contains:
- explicit `Why?` affordance with stable explanation reference and localization-ready `action.why` label key;
- atomic requirement explanation entries with exact requirement IDs, outcomes and unchanged machine-readable reason codes;
- governed source explanation entries with source ID, authority, jurisdiction, source type, exact source version, locator/effective metadata, verification state and content hash;
- governed evidence explanation entries from the exact assessment EvidenceSnapshot with evidence ID/class/kind/content reference/hash, verification state and source ID/version;
- decision provenance identity, actor/evaluator, evaluation instant and exact rule set/version.

## Identity binding
Composition fails closed unless Credential Card and EligibilityAssessment match exactly on:
- Subject;
- assessment ID;
- CredentialDefinition ID and version;
- RequirementSet ID and version;
- eligibility outcome;
- authoritative evaluation instant.

This prevents a `Why?` explanation from being attached to the wrong historical assessment/version.

## Reason semantics
Reason codes are copied exactly from governed `AtomicRequirementResult.reasonCodes` and are never translated, rewritten, merged, ranked or generated by Slice 04. Human-readable localization or AI explanation may be added later only as a non-authoritative rendering over these stable codes/references.

## Source semantics
Source metadata is direct passthrough from governed `SourceReference`. Slice 04 does not infer source authority, applicability, supersession, legal force or current effect beyond what the source reference already contains.

## Evidence semantics
Evidence metadata is direct passthrough from the exact immutable `EvidenceSnapshot`. Slice 04 does not promote derived evidence, infer verification, or manufacture evidence-to-reason relationships that are absent from authoritative data.

## Why? affordance
`WhyAffordance` is navigation/presentation metadata only:
- kind `WHY`;
- target `ELIGIBILITY`;
- label key `action.why`;
- stable explanation reference `calpq:explanation:eligibility:<assessmentId>`;
- `decisionAuthority = false`.

The affordance does not itself explain, decide or authorize anything.

## Hard boundaries
- no reason-code invention or semantic rewriting;
- no eligibility or verification re-evaluation;
- no generic validity/current/legal conclusion;
- no `AuthorizationGrant` issuance or implication;
- no M04 Credential Catalog / QualificationPath ownership;
- no M06 lifecycle authority;
- no provider SDK or UI framework dependency;
- no ambient wall-clock or randomness;
- no AI-generated content inside the authoritative explanation read model.

## Recovery / migration
No schema or data migration. Slice 04 is additive and reversible without changing M02 authoritative state/history or prior M03 read contracts.
