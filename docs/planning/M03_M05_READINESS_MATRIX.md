# CALPQ M03-M05 Planning Readiness Matrix

Status: `PLANNING ONLY / BLOCKED`
ID: `CALPQ-M03-M05-READINESS-0001`

The following 30 criteria are mandatory before this planning block may be classified as ready for future milestone admission.

1. M03 dashboard is projection/read oriented and contains no hidden domain mutation.
2. M03 Professional Passport is explicitly non-authoritative.
3. M03 Credential Cards separate artifact, verification, eligibility, authorization and lifecycle states.
4. M03 material statuses provide a `why`/explanation path.
5. M03 user-facing source/provenance indicators are defined.
6. M03 timeline preserves historical/versioned references.
7. M03 search cannot create facts or verification state.
8. M03 mobile/web read flows share the same Application/contracts boundary.
9. M03 accessibility is not color-only and supports semantic status labels.
10. M03 localization cannot alter Core date/time or reason-code semantics.
11. M04 Activity/Profession/Credential/Requirement catalog ownership is explicit.
12. M04 catalog entities use stable IDs/codes and version/effective dating.
13. M04 QualificationPath references exact target/jurisdiction/version.
14. M04 RequirementSet changes create new versions rather than rewriting history.
15. M04 equivalence/recognition remains separate from AuthorizationGrant.
16. M04 Gap Navigator evaluates one exact subject context against one exact target path/version.
17. M04 gap outputs preserve reason codes and source/evidence references.
18. M04 ambiguity produces review/indeterminate state rather than guessed applicability.
19. M04 query/search does not invent requirements or legal scope.
20. M04 outputs can feed M03 without duplicating domain truth.
21. M05 every intake channel maps to one governed intake lifecycle.
22. M05 immutable original and derived/extracted content are separate records.
23. M05 user correction is attributable/versioned and does not mutate original evidence.
24. M05 technical verification is distinct from verifier/issuer authority resolution.
25. M05 provider outage cannot be converted into successful or failed claim semantics automatically.
26. M05 malware/untrusted-content quarantine is part of intake planning.
27. M05 tenant/storage/privacy boundaries are explicit.
28. M05 VerificationRecord preserves method, verifier, claims, source/version, time and provenance.
29. M03-M05 ownership rules prevent UI, catalog and intake layers from redefining Core truth.
30. M03-M05 implementation remains blocked until separately admitted under project governance.

## Planning exit
Planning readiness requires all 30 criteria, all baseline/integration documents, and the planning guard to pass. Passing this matrix is not implementation authorization.
