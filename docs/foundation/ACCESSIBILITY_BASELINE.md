# CALPQ Accessibility Baseline

Status: `M00 FOUNDATION / NORMATIVE`  
ID: `CALPQ-A11Y-0001`  
Date: `2026-09-13`

## Target

Web experiences target WCAG 2.2 AA as the minimum product baseline unless a stricter applicable requirement supersedes it. Native mobile experiences must use platform accessibility semantics and conventions in addition to equivalent CALPQ acceptance criteria.

## Mandatory acceptance criteria

- Important meaning never relies on color alone.
- Interactive controls have meaningful accessible names, roles and states.
- Keyboard/focus navigation is logical on interfaces where keyboard input is supported.
- Text scaling/reflow must not hide essential content or actions.
- Errors identify the affected field/state and provide understandable recovery guidance.
- Focus is not trapped or moved unexpectedly without a justified interaction pattern.
- Motion/animation must respect platform reduced-motion preferences where applicable.
- Status, warning and validation information is exposed to assistive technologies.
- Touch/click targets and input patterns follow platform accessibility guidance.
- Screen-reader and keyboard verification is included for critical user journeys before release.

## Exceptions

An accessibility exception requires explicit documentation of scope, user impact, reason, mitigation and an owner/date for review. Accessibility is not waived by visual design preference.
