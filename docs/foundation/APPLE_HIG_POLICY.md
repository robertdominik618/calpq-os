# Apple HIG Policy

Status: `M00 FOUNDATION / NORMATIVE`  
ID: `CALPQ-HIG-0001`

CALPQ user experiences targeting Apple platforms must follow Apple Human Interface Guidelines as a design baseline while preserving CALPQ legal, security, privacy and accessibility constraints.

## Rules

- Prefer clear hierarchy, progressive disclosure and familiar platform conventions.
- Keep primary actions obvious and destructive actions explicit.
- Do not encode critical meaning by color alone.
- Design for Dynamic Type, VoiceOver and keyboard/assistive navigation where supported.
- Respect platform privacy expectations and request access only when needed and explained.
- Use native interaction patterns where they improve predictability; visual imitation must never replace correct semantics.
- UI is presentation and intent capture; business rules remain outside UI.
- Error states must explain what happened, what is affected and the next safe action.
- Legal/source provenance must remain inspectable where the user relies on regulated or time-sensitive information.

## Review gate

Any Apple-facing feature must include an HIG/accessibility review before release. HIG compliance never overrides binding law, security, privacy or CALPQ Constitution.
